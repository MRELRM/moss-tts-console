接口要点

    
    
      
  • MOSS API 域名是 api.mosi.cn（不是 moss.cn），端点在 /v1 路径下；鉴权统一使用 Authorization: Bearer <Key>。
    • 
      
  • 单音色 POST /v1/audio/speech（moss-tts-1.5-flash）；多人对话 POST /v1/audio/speech/speakers（moss-ttsd-1.0，speakers 声明说话人 + segments 按顺序给台词）；音色设计 POST /v1/audio/voice/generations（moss-voice-generator-1.0，返回风格预览音频，不产生可复用的 voice_id）；音色克隆 POST /v1/audio/voices（multipart/form-data，返回音色对象 id 即 voice_id）。
    • 
      
  • delivery_method：audio 直接返回音频二进制；url 返回 JSON 与结果 URL。音色设计建议用 url 方式。
    • 
      
  • 音色克隆的字段名（默认 file）在文档未明确时可在 .env 中通过 MOSS_CLONE_FILE_FIELD 调整。
    • 
    

  

  

    
本地与安全

    
    
      
  • API Key 只保存在服务端 .env，浏览器端代码与网络请求中均不出现密钥；修改 .env 后需重启 node server.js。
    • 
      
  • 相同请求（endpoint + 参数的 SHA-256）命中本地缓存 .cache/moss/，不再调用 MOSS API、不重复消耗积分；清空缓存可直接删除该目录。URL 模式的结果 URL 可能有时效，过期后清缓存重新生成即可。
    • 
      
  • 健康检查 GET /api/health；下载代理 GET /api/proxy-download 仅允许 MOSS 相关域名。
